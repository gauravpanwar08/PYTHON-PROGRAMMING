# SQLAlchemy ORM Practical Project

A standalone Python + SQLAlchemy ORM + PostgreSQL project demonstrating:
- Six related tables: users, projects, project_members, tasks, task_assignees, comments
- Declarative models, relationships, association objects, constraints and indexes
- CRUD, filtering, joins, aggregation, loader strategies, transactions
- Hybrid properties, ORM events, bulk operations, pagination
- Alembic migrations

## 1. Requirements
- Python 3.10+
- PostgreSQL running locally
- A database named `sqlalchemy_db` (create it before running migrations)

## 2. Setup (Windows PowerShell)
```powershell
py -3.10 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

Edit `.env` and set your PostgreSQL credentials. `DATABASE_URL` is built with `URL.create()` so passwords containing special characters are handled safely.

Create the database if it does not exist:
```sql
CREATE DATABASE sqlalchemy_db;
```

## 3. Run migrations
```powershell
alembic upgrade head
python -m app.seed
```

Do not use `Base.metadata.create_all()` for this project's production-style schema setup; Alembic owns schema changes.

## 4. Run the demo
```powershell
python -m app.demo
```

The demo is designed to be repeatable: it finds or creates the sample users/projects, creates missing memberships/tasks/assignments/comments, and prints example queries. It does not delete your data.

## 5. Useful commands
```powershell
alembic current
alembic history
alembic revision --autogenerate -m "describe schema change"
alembic upgrade head
alembic downgrade -1
```

Always review autogenerated migration files before applying them.

## 7. Tables and relationships
1. `users` — identity/contact and timestamps
2. `projects` — project metadata and status
3. `project_members` — association object between users and projects, including role
4. `tasks` — project tasks with status, priority, dates
5. `task_assignees` — association object between users and tasks
6. `comments` — comments authored by users on tasks

Important design note: user/project/task deletion is deliberately restrictive at the database FK level for ownership/history safety. Task comments and association rows use explicit ORM cascade where configured. Review deletion policies before adapting this for a real production app.
